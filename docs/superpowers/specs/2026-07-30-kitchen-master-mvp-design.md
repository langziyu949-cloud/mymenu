# 《厨房主理人》MVP 产品与技术设计

- 版本：V1.0
- 日期：2026-07-30
- 状态：已完成讨论，待书面确认
- 产品形态：HarmonyOS 手机应用
- 首台目标设备：HUAWEI Mate X5，HarmonyOS 6.1
- 分发方式：DevEco Studio 签名后真机安装，不公开上架

## 1. 产品定义

“厨房主理人”是一款本地优先的 AI 家庭菜谱记录工具。

用户用自然语言描述一道做成功的菜，AI 将描述整理成简洁的结构化菜谱。用户在对话中确认或修改内容，选择是否添加成品照片，然后把卡片收进自己的菜谱夹。

MVP 只验证一件事：

> 用户是否能在三分钟内，把一次成功的做菜经验整理成一份愿意长期保存和再次使用的个人菜谱。

## 2. MVP 原则

1. 先服务一名真实用户和一台真实设备。
2. 记录体验优先于字段完整度。
3. AI 可以帮助补全食材、调料及用量，但不能虚构用户经验。
4. 菜谱和照片本地保存；只有文字在用户主动整理时上传到云端 AI。
5. 不因为缺少照片或非关键字段阻止保存。
6. 为未来家庭共享预留数据边界，但不提前实现账号和同步。
7. 测试保持轻量，以构建稳定和真机体验为主。

## 3. MVP 范围

### 3.1 包含

- 自然语言长文本输入。
- 通过系统输入法使用语音输入。
- DeepSeek 菜谱结构化整理。
- 一轮、最多三个关键追问。
- 对话式菜谱确认和修改。
- AI 估算食材、调料及用量。
- 菜谱完成后拍照或从相册选择照片。
- 无照片时使用统一默认封面。
- 卡片收纳动效。
- 本地菜谱数据库。
- 本地草稿自动保存和恢复。
- 菜谱列表、详情、编辑和删除。
- 按菜名、食材或调料搜索。
- 离线查看、搜索和编辑已有菜谱。
- “我的”中的隐私说明、AI 服务状态和产品信息。

### 3.2 不包含

- 应用内录音、麦克风权限和语音转写。
- 图片识别菜谱。
- AI 图片生成或照片重绘。
- 登录、账号和用户身份系统。
- 云端菜谱库和跨设备同步。
- 数据备份与导入导出。
- 家庭空间和菜谱分享。
- 推荐、营养分析、采购清单和社区。
- 应用市场公开上架。
- 独立的动态效果设置。

## 4. 菜谱结构

### 4.1 用户可见字段

每道菜谱只展示：

1. 菜名。
2. 食材及用量。
3. 调料及用量。
4. 制作步骤。
5. 经验建议列表。
6. 照片。
7. 创建时间。

菜名和制作步骤为必填项。其他字段允许为空。

时间、火候和完成标准直接写在对应步骤的自然语言文本中，不拆成独立字段。

### 4.2 内部技术字段

为本地管理和未来同步预留：

- 全局唯一菜谱 ID。
- 本机所有者 ID。
- 草稿或已保存状态。
- 创建时间和更新时间。
- 数据版本号。
- 删除时间。
- 原始用户描述。
- AI 估算标记。
- 食材、调料和步骤的排序值。

这些字段不作为菜谱内容展示。

## 5. AI 行为设计

### 5.1 首次分析

AI 接收用户原始描述后：

1. 提取菜名。
2. 从描述和步骤中提取食材、调料及用量。
3. 按用户描述整理制作步骤。
4. 提取用户明确表达的经验建议。
5. 判断是否必须追问。

### 5.2 追问规则

只在以下情况追问：

- 无法确定菜名。
- 无法形成有效制作步骤。
- 用户描述存在影响做法的明显冲突。
- 关键食材或调料无法从上下文合理判断。

追问只进行一轮，每轮最多三个问题。用户可以跳过。

菜名或步骤仍为空时不能最终保存；其他信息即使缺失也可以保存。

### 5.3 智能补全

AI 可以：

- 从“加入番茄翻炒”补出食材“番茄”。
- 从“放生抽调味”补出调料“生抽”。
- 在上下文足够时估算食材或调料用量。

AI 补出的用量在草稿中显示轻量“AI 估算”标记。用户修改某项后，该项标记消失；用户点击“完成菜谱”代表接受其余估算，正式保存后的详情页不再显示估算标记。

### 5.4 禁止行为

AI 不可以：

- 虚构用户没有表达的成功经验。
- 为填满字段而生成通用经验建议。
- 在没有充分上下文时编造菜名或关键步骤。
- 用一次修改指令重写无关字段。

### 5.5 对话修改

菜谱卡片生成后，用户可以继续用自然语言修改，例如：

- “老抽改成半勺。”
- “把第三步移到第二步前面。”
- “经验里加上番茄要分两次放。”

后端接收当前结构化菜谱和修改指令，只返回更新后的完整菜谱。客户端只有在新结果通过结构校验后才替换现有卡片。

## 6. 页面与导航

底部导航固定为：

- 左侧：菜谱。
- 中间：`+`。
- 右侧：我的。

中间 `+` 是核心记录入口，同时也是应用默认首页。它的无障碍名称为“记录一道菜”，视觉上以突出按钮呈现。

### 6.1 AI 对话首页

无草稿时：

- 展示 AI 问候和简短输入提示。
- 展示长文本输入框。
- 不展示照片按钮。
- 提示用户可以使用系统输入法语音。

有草稿时：

- 自动恢复原始描述、AI 追问、用户回答和当前卡片。
- 点击中间 `+` 返回该草稿。
- 页面菜单提供“放弃并记录新菜”，执行前二次确认。

### 6.2 对话确认

- AI 消息和用户消息按时间排列。
- 结构化菜谱以卡片形式嵌入对话。
- 用户通过文字指令修改卡片。
- 卡片突出显示尚未确认的 AI 估算用量。
- 内容满足必填条件后显示“完成菜谱”。

### 6.3 照片询问

用户点击“完成菜谱”后，才弹出照片选择：

- 拍一张。
- 从相册选择。
- 暂时不要，使用默认封面。

弹窗明确说明：

> 照片只作为菜谱封面，不会用于识别或修改菜谱内容。

照片选择、读取或复制失败时使用默认封面，不阻止保存。

### 6.4 保存动效

数据库保存成功后：

1. 当前菜谱卡片保持完整展示。
2. 卡片在约 900 毫秒内逐渐收束和拉伸，形成类似 macOS 窗口最小化的柔性“精灵缩放”效果。
3. 卡片吸入左下角“菜谱”按钮。
4. 菜谱按钮在动效结束时回弹或发光。
5. 应用切换到菜谱页，新卡片在列表首位高亮 1.2 秒。

动效是保存成功的结果，不得在数据库提交前播放。

当系统启用减少动态效果时，自动退化为 200 毫秒缩小和淡出；应用内不提供独立开关。

### 6.5 菜谱页

- 标题为“我的菜谱夹”。
- 展示菜谱数量。
- 提供搜索框。
- 以创建时间倒序展示卡片。
- 卡片显示照片或默认封面、菜名和创建日期。
- 搜索范围包含菜名、食材名称和调料名称。
- 点击卡片进入详情。

### 6.6 菜谱详情与编辑

详情按以下区块展示：

- 菜名。
- 食材与用量。
- 调料与用量。
- 制作步骤。
- 经验建议。
- 照片和创建时间。

用户可直接编辑某个区块，而不需要再次进入 AI 对话。支持更换照片和删除菜谱。

删除需要确认，并提供五秒撤销入口。

### 6.7 我的

MVP 包含：

- 本机数据说明。
- 隐私说明。
- AI 服务状态。
- 关于“厨房主理人”。

不包含账号、登录、同步和动态效果开关。

## 7. 技术架构

### 7.1 总体方案

采用：

> HarmonyOS 原生客户端 + 本地关系型数据库 + 腾讯云函数代理 + DeepSeek

客户端不直接持有 DeepSeek API Key。

### 7.2 客户端

使用 DevEco Studio、ArkTS 和 ArkUI 原生开发。

客户端划分为：

1. 页面层：AI 对话、菜谱、详情编辑和“我的”。
2. 业务层：草稿、AI 整理、修改、保存、搜索和删除。
3. 数据层：统一的 Recipe Repository。
4. 基础设施层：关系型数据库、照片文件、网络客户端和动效组件。

页面不得直接执行 SQL 或操作照片文件。

### 7.3 本地数据库

使用四组数据：

#### recipes

- id
- ownerId
- name
- experienceJson
- photoPath
- originalText
- status
- createdAt
- updatedAt
- version
- deletedAt

#### recipe_items

- id
- recipeId
- type：ingredient 或 seasoning
- name
- amount
- isAiEstimated
- sortOrder

#### recipe_steps

- id
- recipeId
- content
- sortOrder

#### draft_sessions

- id
- originalText
- answersJson
- conversationJson
- currentRecipeJson
- updatedAt

照片复制到应用私有目录，数据库只保存内部路径。

菜谱保存使用单个数据库事务。数据库提交失败时清理本次复制的临时照片。正式保存成功后删除对应的 draft_sessions 记录和对话消息，只在 recipes 中保留原始描述。

删除时先写入 deletedAt 并从正常查询中隐藏。五秒撤销期结束后，物理删除菜谱、关联项、步骤和照片。

### 7.4 后端

使用 TypeScript 编写轻量 HTTP 服务。

开发阶段在电脑本地运行；真机流程稳定后部署到腾讯云函数，通过 Function URL 暴露 HTTPS 接口。

后端不保存菜谱，只负责：

- 请求校验。
- 单设备访问令牌校验。
- 请求体上限 64 KB。
- 调用 DeepSeek。
- JSON 结构校验。
- 空响应、截断或非法 JSON 的一次自动重试。
- 错误码标准化。
- 隐私化日志。

DeepSeek API Key 存放在云函数环境变量中。

### 7.5 后端接口

#### POST /api/v1/recipes/analyze

输入：

- 原始描述。
- 可选的追问回答。

输出二选一：

- questions：最多三个问题。
- recipe：结构化菜谱。

#### POST /api/v1/recipes/revise

输入：

- 当前结构化菜谱。
- 用户修改指令。

输出：

- 修改后的完整结构化菜谱。

#### GET /api/v1/health

用于“我的”页面显示 AI 服务是否可用，不调用模型。

## 8. 核心数据流

1. 用户输入文字。
2. 客户端立即创建或更新本地草稿。
3. 客户端调用 analyze。
4. 后端返回问题或菜谱。
5. 用户回答问题或继续修改。
6. 客户端保存每一次通过校验的菜谱状态。
7. 用户点击“完成菜谱”。
8. 客户端询问是否添加照片。
9. 客户端复制选中的照片，或使用默认封面。
10. 客户端在数据库事务中保存菜谱。
11. 事务成功后播放吸入左下角菜谱按钮的动效。
12. 客户端切换至菜谱页并高亮新卡片。

## 9. 异常处理

### 9.1 草稿

- MVP 同时只保留一个未完成草稿。
- 输入、回答、对话状态和当前卡片均自动保存。
- 应用退出、切后台、进程被杀或折叠状态变化后恢复草稿。

### 9.2 网络和 AI

- 请求前先保存草稿。
- 请求期间禁用重复提交。
- 客户端请求超时为 30 秒，超时后由用户手动重试。
- 网络失败不修改当前卡片。
- DeepSeek 无效响应由后端自动重试一次。
- 重试失败后显示可操作的“重新整理”或“重新修改”。

### 9.3 保存

- 菜名或步骤为空时禁止完成。
- 数据库保存失败时停留在当前页面。
- 保存失败不播放归档动画。
- 照片失败不影响菜谱正文保存。

### 9.4 删除

- 删除前确认。
- 删除后允许在五秒内撤销。
- 撤销期结束后物理删除菜谱、关联项、步骤和照片。

## 10. 隐私与安全

- 不申请麦克风权限。
- 对话界面不展示照片入口。
- 照片不上传到 DeepSeek、腾讯云或其他服务。
- 只在用户主动整理或修改时上传必要文字。
- 腾讯云函数不持久化菜谱正文。
- 服务日志不记录菜谱原文、访问令牌或 DeepSeek Key。
- DeepSeek Key 只存在于云函数环境变量。
- 客户端使用可撤销的单设备访问令牌。
- 后端将请求体限制为 64 KB，并把腾讯云函数最大并发数设置为 2，控制异常调用成本。
- “我的”页面提供清晰的隐私说明。

## 11. 分发与运行

### 11.1 MVP

- 通过 DevEco Studio 自动或手动签名。
- 使用开发者模式将 HAP 安装到 Mate X5。
- 保持包名和签名稳定。
- 更新时覆盖安装，不先卸载，避免本地菜谱被清除。

### 11.2 后续

需要给家庭成员使用时，可使用 AppGallery Connect 内部测试。内部测试不等于公开上架。

正式公开上架不属于本次 MVP。

## 12. 轻量测试策略

自动化只覆盖容易造成数据或密钥事故的核心逻辑：

- 菜谱必填字段校验。
- 本地数据库保存、搜索和事务回滚。
- 后端请求与响应结构校验。
- DeepSeek 空响应或非法 JSON 的重试。
- 日志与客户端包不包含 DeepSeek Key。

准备五条固定中文描述做提示词冒烟回归，不建设复杂模型评测系统。

开发阶段执行：

- ArkTS 构建和静态检查。
- 后端类型检查和核心单元测试。
- 一条端到端正常流程。
- 一条网络失败与草稿恢复流程。

最终由用户在 Mate X5 上按简短清单进行体验验收。

## 13. MVP 完成标准

满足以下条件即可认为 MVP 完成：

1. 用户能在三分钟内记录一条正常菜谱。
2. 菜名和制作步骤不会为空。
3. 描述不清时，AI 一轮内最多追问三个关键问题。
4. AI 能从步骤中补充食材、调料和合理用量，并标记估算内容。
5. AI 不生成用户未表达的经验建议。
6. 用户能通过对话修改草稿。
7. 完成后才询问照片，照片不参与 AI 识别。
8. 保存后卡片吸入左下角菜谱入口。
9. 菜谱可以查看、搜索、编辑和删除。
10. 应用重启或切换折叠状态后草稿不丢失。
11. 无网络时已有菜谱仍可使用。
12. DeepSeek Key 不出现在客户端和日志中。
13. Mate X5 上核心流程无崩溃和数据丢失。

## 14. 后续家庭共享演进

MVP 不实现家庭共享，但保留下列演进路径：

1. 本地 Recipe Repository 可替换或组合云端 Repository。
2. 菜谱使用全局唯一 ID、ownerId、version 和 deletedAt。
3. 增加账号后，将本机 ownerId 映射为正式用户。
4. 云端增加家庭、成员、共享权限和同步接口。
5. 共享对象沿用现有菜谱结构，不要求重建客户端页面。

家庭共享开始开发时，需要单独完成产品设计、权限模型和同步冲突方案。
